# Atividade Pratica - Aula 04: Arquitetura HTTP, Rotas e APIs RESTful

Este repositorio contem a resolucao da bateria de exercicios praticos da Aula 04, focada no entendimento da anatomia do protocolo HTTP, utilizacao correta de metodos/verbos, manipulacao de parametros (Query Params e Path Params), tratamento de Status Codes e automacao de testes CRUD.

---

## Exercicios de Fixacao

* **EXERCICIO 01:** Efetue uma requisicao GET buscando apenas o veiculo de ID 1 e exiba o resultado formatado com 'jq'.
* **EXERCICIO 02:** Cadastre um novo caminhao da montadora 'Volvo' (modelo 'FH 540', placa 'KLL-9090') enviando uma requisicao POST via cURL ou httpie. Verifique se o retorno e o status HTTP 201 Created.
* **EXERCICIO 03:** Tente cadastrar um veiculo sem passar o campo 'placa' no body da requisicao. Confirme se a API retorna o status 400 Bad Request com a mensagem de erro apropriada.
* **EXERCICIO 04:** Faça uma requisicao GET filtrando os veiculos por query param: 'http://localhost:3000/api/v1/veiculos?status=DISPONIVEL'.
* **EXERCICIO 05:** Atualize o status do veiculo de ID 3 para 'EM_ROTA' utilizando a rota PATCH.
* **EXERCICIO 06:** Tente atualizar ou deletar um veiculo com um ID inexistente (ex: ID 99) e valide se o status code retornado e 404 Not Found.
* **EXERCICIO 07:** Adicione uma nova rota PUT na API (`/api/v1/veiculos/:id`) que permite substituir todos os dados de um veiculo de uma so vez.
* **EXERCICIO 08:** Crie um script Bash chamado 'teste_crud.sh' que executa sequencialmente o cadastro de 2 veiculos, atualiza 1 deles e deleta o outro, registrando os logs em 'crud_result.log'.

## Exercicio 01: Consulta por ID com Path Param e jq

### Objetivo
Realizar uma busca pontual de um recurso especifico utilizando um parametro de rota (Path Parameter) para recuperar os dados do primeiro veiculo cadastrado.

### Comando Executado
```bash
curl -s http://localhost:3000/api/v1/veiculos/1 | jq .
```

### Explicacao Tecnica
O numero `1` ao final da URL funciona como um Path Parameter mapeado no Express pela rota `/api/v1/veiculos/:id`. O servidor intercepta essa string, converte-a em um numero inteiro via `parseInt(req.params.id)` e faz a busca no array em memoria. A flag `-s` do cURL omite os dados de download e o pipe `| jq .` renderiza a resposta estruturada com indentacao no terminal.

## Exercicio 02: Persistencia de Recursos com POST e Status 201

### Objetivo
Cadastrar um novo veiculo na base de dados enviando um payload JSON estruturado no corpo da requisicao e validar se o servidor retorna o codigo de sucesso correto de criacao.

### Comando Executado
```bash
curl -s -i -X POST http://localhost:3000/api/v1/veiculos -H "Content-Type: application/json" -d '{"placa":"KLL-9090","montadora":"Volvo","modelo":"FH-540"}'
```

### Explicacao Tecnica
Usamos a flag `-X POST` para especificar o metodo HTTP de criacao. O header `-H "Content-Type: application/json"` e obrigatorio para avisar o middleware `express.json()` que o corpo enviado (`-d`) esta formatado como um objeto JSON. A flag `-i` (include) foi inserida para imprimir os cabecalhos de resposta da API no terminal, permitindo comprovar visualmente o retorno do status `HTTP/1.1 201 Created`.

## Exercicio 03: Validacao de Payload com Status 400 Bad Request

### Objetivo
Simular uma quebra de contrato de API enviando um objeto incompleto para o endpoint de cadastro, validando a robustez defensiva do servidor.

### Comando Executado
```bash
curl -s -i -X POST http://localhost:3000/api/v1/veiculos -H "Content-Type: application/json" -d '{"montadora":"Volvo","modelo":"FH 540"}'
```

### Explicacao Tecnica
A rota intercepta a falta do campo de identificacao obrigatorio por meio da condicional `if (!placa || !montadora || !modelo)`. Como a chave `placa` foi omitida do corpo da requisicao, o fluxo de criacao e interrompido imediatamente e o servidor devolve um cabecalho `HTTP/1.1 400 Bad Request` junto a um objeto JSON descrevendo o erro para o cliente.

## Exercicio 04: Filtragem de Dados com Query Params

### Objetivo
Realizar uma consulta de listagem aplicando um filtro dinâmico por meio de parâmetros de busca na URL (Query Parameters) para trazer apenas os veículos disponíveis.

### Comando Executado
```bash
curl -s "http://localhost:3000/api/v1/veiculos?status=DISPONIVEL" | jq .
```

### Explicacao Tecnica
O caractere `?` na URL separa o caminho do recurso dos seus parâmetros de consulta. No Express, a chave e o valor configurados após o sinal de igual são capturados através do objeto `req.query`. O servidor avalia a presença da variável, executa o método `.filter()` no array em memória ignorando diferenças entre maiúsculas e minúsculas, e devolve o conjunto filtrado com o status `200 OK`.

## Exercicio 05: Modificacao Parcial com o Metodo PATCH

### Objetivo
Atualizar de forma isolada e específica o status de um veículo existente na base de dados utilizando o identificador de ID na rota.

### Comando Executado
```bash
curl -s -X PATCH http://localhost:3000/api/v1/veiculos/3 -H "Content-Type: application/json" -d '{"status":"EM_ROTA"}' | jq .
```

### Explicacao Tecnica
O método PATCH é o verbo HTTP indicado semanticamente para modificações parciais em um recurso. A rota localiza o registro correspondente ao veículo inserido no Exercício 02 (ID 3), valida a presença do campo `status` no corpo da requisição e altera o valor da propriedade no array global, devolvendo o objeto modificado e uma mensagem de confirmação.

## Exercicio 06: Tratamento de Recursos Inexistentes com Status 404 Not Found

### Objetivo
Garantir o tratamento correto do ciclo de vida da API disparando requisições para IDs que não existem na base de dados, validando o retorno do status de erro correto.

### Comandos Executados
```bash
# 1. Testando erro 404 em tentativa de atualizacao de ID inexistente
curl -s -i -X PATCH http://localhost:3000/api/v1/veiculos/99 -H "Content-Type: application/json" -d '{"status":"EM_ROTA"}'

# 2. Testando erro 404 em tentativa de remocao de ID inexistente
curl -s -i -X DELETE http://localhost:3000/api/v1/veiculos/99
```

### Explicacao Tecnica
Em ambos os métodos da API, as funções de busca `.find()` ou `.findIndex()` retornam `undefined` ou `-1` quando o ID consultado não existe. O código intercepta essa condição nula nas estruturas condicionais e impede que a lógica prossiga, respondendo ao terminal com o cabeçalho padrão `HTTP/1.1 404 Not Found` acompanhado de um payload descritivo de erro.

## Exercicio 07: Substituicao Completa com o Metodo PUT

### Objetivo
Adicionar um novo endpoint na API utilizando o verbo PUT para permitir a substituicao total de todos os dados de um veiculo existente de uma unica vez na base de dados.

### Codigo Original (frota_api.js)
O servidor original contava apenas com rotas para listagem, busca por ID, criacao via POST, atualizacao parcial via PATCH e remocao via DELETE:

```javascript
// ... rotas anteriores gerenciando o CRUD basico
app.listen(PORT, () => { ... });
```

### Codigo Alterado (frota_api.js)
Editamos o arquivo `frota_api.js` utilizando o editor de terminal (`nano frota_api.js`) e inserimos a nova rota PUT antes do metodo `app.listen` para receber e sobrepor o payload completo:

```javascript
// ... rotas anteriores permanecem iguais

// Nova Rota PUT adicionada para o Exercicio 07
app.put('/api/v1/veiculos/:id', (req, res) => {
    const id = parseInt(req.params.id);
    const { placa, montadora, modelo, status } = req.body;
    const veiculo = veiculos.find(v => v.id === id);

    if (!veiculo) {
        return res.status(404).json({ erro: "Veiculo nao encontrado para substituicao." });
    }
    if (!placa || !montadora || !modelo || !status) {
        return res.status(400).json({ erro: "Todos os campos (placa, montadora, modelo, status) sao obrigatorios para o metodo PUT." });
    }

    // Substitui todos os dados antigos pelos novos recebidos do cliente
    veiculo.placa = placa;
    veiculo.montadora = montadora;
    veiculo.modelo = modelo;
    veiculo.status = status.toUpperCase();

    res.status(200).json({ mensagem: "Veiculo substituido com sucesso!", veiculo });
});

app.listen(PORT, () => {
    console.log(`[Binario Tech] API de Frotas rodando em http://localhost:${PORT}`);
});
```

### Comando Executado para Teste
```bash
curl -s -X PUT http://localhost:3000/api/v1/veiculos/1 -H "Content-Type: application/json" -d '{"placa":"NEW-0000","montadora":"Scania Nova","modelo":"R500","status":"DISPONIVEL"}' | jq .
```

### Passo de Verificacao (Confirmando o Sucesso do Teste)
Para comprovar que o metodo PUT substituiu os dados antigos do registro de ID 1, disparamos a busca isolada logo em seguida:
```bash
curl -s http://localhost:3000/api/v1/veiculos/1 | jq .
```
> **Resultado esperado:** O payload retornado deve exibir as propriedades totalmente atualizadas (`"placa": "NEW-0000"`, `"montadora": "Scania Nova"`, etc.), comprovando que o objeto antigo foi completamente sobreposto na memoria do servidor.

### Explicacao Tecnica
O metodo PUT serve semanticamente para atualizacoes completas (substituicao ou idempotencia do recurso). O bloco de codigo valida obrigatoriamente se todos os atributos foram enviados no corpo da requisicao (`req.body`). Caso algum esteja ausente, ele retorna o erro `400 Bad Request`. Estando todos presentes, o ponteiro local altera cada propriedade do objeto correspondente localizado dentro do array em memoria.

## Exercicio 08: Script Bash de Automacao de Testes CRUD

### Objetivo
Criar um script em Bash automatizado que executa uma rotina sequencial completa de testes na API (cadastra dois veiculos, atualiza um deles e deleta o outro), redirecionando e registrando todas as respostas em um arquivo de log acumulativo.

### Codigo Alterado (Criacao do teste_crud.sh)
Criamos o arquivo do script utilizando o editor de terminal na raiz da pasta `aula04`:
```bash
nano teste_crud.sh
```

**Conteudo do script (`aula04/teste_crud.sh`):**
```bash
#!/bin/bash
# Script de Automacao de Testes - Binario Tech

echo "=========================================" > crud_result.log
echo "  INICIANDO TESTES DA API - BINARIO TECH " >> crud_result.log
echo "  Data/Hora: $(date)" >> crud_result.log
echo "=========================================" >> crud_result.log

echo -e "\n Cadastrando Veiculo A..." >> crud_result.log
curl -s -X POST http://localhost:3000/api/v1/veiculos \
  -H "Content-Type: application/json" \
  -d '{"placa":"AAA-1111","montadora":"Volvo","modelo":"VM"}' >> crud_result.log

echo -e "\n Cadastrando Veiculo B..." >> crud_result.log
curl -s -X POST http://localhost:3000/api/v1/veiculos \
  -H "Content-Type: application/json" \
  -d '{"placa":"BBB-2222","montadora":"DAF","modelo":"XF"}' >> crud_result.log

echo -e "\n Atualizando Status do Veiculo ID 1..." >> crud_result.log
curl -s -X PATCH http://localhost:3000/api/v1/veiculos/1/status \
  -H "Content-Type: application/json" \
  -d '{"status":"MANUTENCAO"}' >> crud_result.log

echo -e "\n Removendo Veiculo ID 2..." >> crud_result.log
curl -s -X DELETE http://localhost:3000/api/v1/veiculos/2 >> crud_result.log

echo -e "\n-----------------------------------------" >> crud_result.log
echo "Rotina CRUD finalizada! Resultados salvos." >> crud_result.log
```

### Comandos de Execucao e Verificacao
```bash
# 1. Concede permissao de execucao ao script bash
chmod +x teste_crud.sh

# 2. Executa a rotina automatizada
./teste_crud.sh

# 3. Le o relatorio de logs gerado para confirmar o sucesso das operacoes
cat crud_result.log
```

### Passo de Verificacao (Confirmando o Sucesso do Teste)
Para comprovar que a automacao funcionou e as operacoes refletiram corretamente no banco de dados em memoria da API, faca uma consulta geral:
```bash
curl -s http://localhost:3000/api/v1/veiculos | jq .
```
> **Resultado esperado:** A listagem deve exibir o veiculo de ID 1 com o status modificado para `"status": "MANUTENCAO"`, o veiculo de ID 2 nao deve aparecer na lista (removido), e os novos veiculos com placas `AAA-1111` e `BBB-2222` devem estar adicionados com sucesso ao final do payload JSON.

### Explicacao Tecnica
O script Bash atua como uma ferramenta basica de integracao continua de infraestrutura, centralizando chamadas cURL em lote. O operador de redirecionamento simples `>` limpa e reinicia a escrita no arquivo `crud_result.log` a cada nova execucao. Os operadores sequenciais de anexo `>>` inserem as novas linhas de metadados e os payloads JSON devolvidos pela API no final do arquivo de log sem apagar o progresso anterior, permitindo a auditoria completa das respostas de rede.
