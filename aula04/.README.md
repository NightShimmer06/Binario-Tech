# Atividade Pratica - Aula 04: Arquitetura HTTP, Rotas e APIs RESTful

Este repositorio contem a resolucao da bateria de exercicios praticos da Aula 04, focada no entendimento da anatomia do protocolo HTTP, utilizacao correta de metodos/verbos, manipulacao de parametros (Query Params e Path Params), tratamento de Status Codes e automacao de testes CRUD.

## Exercicios de Fixacao

* **EXERCICIO 01:** Efetue uma requisicao GET buscando apenas o veiculo de ID 1 e exiba o resultado formatado com 'jq'.
* **EXERCICIO 02:** Cadastre um novo caminhao da montadora 'Volvo' (modelo 'FH 540', placa 'KLL-9090') enviando uma requisicao POST via cURL ou httpie. Verifique se o retorno e o status HTTP 201 Created.
* **EXERCICIO 03:** Tente cadastrar um veiculo sem passar o campo 'placa' no body da requisicao. Confirme se a API retorna o status 400 Bad Request com a mensagem de erro apropriada.
* **EXERCICIO 04:** Faça uma requisicao GET filtrando os veiculos por query param: 'http://localhost:3000/api/v1/veiculos?status=DISPONIVEL'.

## Exercicio 01: Consulta por ID com Path Param e jq

### Objetivo
Realizar uma busca pontual de um recurso especifico utilizando um parametro de rota (Path Parameter) para recuperar os dados do primeiro veiculo cadastrado.

### Comando Executado
```bash
curl -s http://localhost:3000/api/v1/veiculos/1 | jq .
```

### Explicacao Tecnica
O numero `1` ao final da URL funciona como um Path Parameter mapeado no Express pela rota `/api/v1/veiculos/:id`. O servidor intercepta essa string, converte-a em um numero inteiro via `parseInt(req.params.id)` e faz a busca no array em memoria. A flag `-s` do cURL omite os dados de download e o pipe `| jq .` renderiza a resposta estruturada com indentacao no terminal.

## Exercicio 02: Persistencia de Recursos com POST e Status 201

### Objetivo
Cadastrar um novo veiculo na base de dados enviando um payload JSON estruturado no corpo da requisicao e validar se o servidor retorna o codigo de sucesso correto de criacao.

### Comando Executado
```bash
curl -s -i -X POST http://localhost:3000/api/v1/veiculos \
  -H "Content-Type: application/json" \
  -d '{"placa":"KLL-9090","montadora":"Volvo","modelo":"FH-540"}'
```

### Explicacao Tecnica
Usamos a flag `-X POST` para especificar o metodo HTTP de criacao. O header `-H "Content-Type: application/json"` e obrigatorio para avisar o middleware `express.json()` que o corpo enviado (`-d`) esta formatado como um objeto JSON. A flag `-i` (include) foi inserida para imprimir os cabecalhos de resposta da API no terminal, permitindo comprovar visualmente o retorno do status `HTTP/1.1 201 Created`.

## Exercicio 03: Validacao de Payload com Status 400 Bad Request

### Objetivo
Simular uma quebra de contrato de API enviando um objeto incompleto para o endpoint de cadastro, validando a robustez defensiva do servidor.

### Comando Executado
```bash
curl -s -i -X POST http://localhost:3000/api/v1/veiculos \
  -H "Content-Type: application/json" \
  -d '{"montadora":"Volvo","modelo":"FH 540"}'
```

### Explicacao Tecnica
A rota intercepta a falta do campo de identificacao obrigatorio por meio da condicional `if (!placa || !montadora || !modelo)`. Como a chave `placa` foi omitida do corpo da requisicao, o fluxo de criacao e interrompido imediatamente e o servidor devolve um cabecalho `HTTP/1.1 400 Bad Request` junto a um objeto JSON descrevendo o erro para o cliente.

## Exercicio 04: Filtragem de Dados com Query Params

### Objetivo
Realizar uma consulta de listagem aplicando um filtro dinâmico por meio de parâmetros de busca na URL (Query Parameters) para trazer apenas os veículos disponíveis.

### Comando Executado
```bash
curl -s "http://localhost:3000/api/v1/veiculos?status=DISPONIVEL" | jq .
```

### Explicacao Tecnica
O caractere `?` na URL separa o caminho do recurso dos seus parâmetros de consulta. No Express, a chave e o valor configurados após o sinal de igual são capturados através do objeto `req.query`. O servidor avalia a presença da variável, executa o método `.filter()` no array em memória ignorando diferenças entre maiúsculas e minúsculas, e devolve o conjunto filtrado com o status `200 OK`.

## Exercicio 05: Modificacao Parcial com o Metodo PATCH

### Objetivo
Atualizar de forma isolada e específica o status de um veículo existente na base de dados utilizando o identificador de ID na rota.

### Comando Executado
```bash
curl -s -X PATCH http://localhost:3000/api/v1/veiculos/3/status \
  -H "Content-Type: application/json" \
  -d '{"status":"EM_ROTA"}' | jq .
```

### Explicacao Tecnica
O método PATCH é o verbo HTTP indicado semanticamente para modificações parciais em um recurso. A rota localiza o registro correspondente ao veículo inserido no Exercício 02 (ID 3), valida a presença do campo `status` no corpo da requisição e altera o valor da propriedade no array global, devolvendo o objeto modificado e uma mensagem de confirmação.

## Exercicio 06: Tratamento de Recursos Inexistentes com Status 404 Not Found

### Objetivo
Garantir o tratamento correto do ciclo de vida da API disparando requisições para IDs que não existem na base de dados, validando o retorno do status de erro correto.

### Comandos Executados
```bash
# 1. Testando erro 404 em tentativa de atualizacao de ID inexistente
curl -s -i -X PATCH http://localhost:3000/api/v1/veiculos/99/status \
  -H "Content-Type: application/json" \
  -d '{"status":"EM_ROTA"}'

# 2. Testando erro 404 em tentativa de remocao de ID inexistente
curl -s -i -X DELETE http://localhost:3000/api/v1/veiculos/99
```

### Explicacao Tecnica
Em ambos os métodos da API, as funções de busca `.find()` ou `.findIndex()` retornam `undefined` ou `-1` quando o ID consultado não existe. O código intercepta essa condição nula nas estruturas condicionais e impede que a lógica prossiga, respondendo ao terminal com o cabeçalho padrão `HTTP/1.1 404 Not Found` acompanhado de um payload descritivo de erro.
