Este repositorio contem a resolucao da bateria de exercicios praticos da Aula 05, focada na arquitetura de Middlewares no Express, modularizacao de endpoints com Express Router, politicas de seguranca com CORS e tratamento global de erros.

## Exercicio 01: Inspecao de Ciclo de Vida de Middleware de Log

### Objetivo
Disparar uma requisicao contra o endpoint publico de saude da aplicacao e auditar a interceptacao dos metadados de rede gerados pelo middleware customizado de log no console do servidor.

### Comando Executado no Terminal
```bash
curl -s http://localhost:3005/api/v1/health | jq .
```

### Exemplo de Logs Capturados no Console
```text
[LOG 2026-10-02T16:10:00.123Z] GET /api/v1/health - Status: 200 (5ms)
```

### Explicacao Tecnica
O `loggerMiddleware` intercepta a requisicao HTTP antes de atingir o handler final. Ele registra a funcao temporizadora inicial e aciona o evento `res.on('finish')`. Quando os buffers de resposta sao completamente descarregados para o cliente (Status 200 OK), o gatilho calcula a diferenca de milissegundos e imprime a linha cronologica formatada, provando o encerramento do ciclo de vida da conexao.

## Exercicio 02: Criacao do Roteador Modular de Manutencoes

### Objetivo
Construir um novo arquivo de rota isolado utilizando o componente Express Router para gerenciar de forma modularizada a listagem e o cadastro de orcamentos de manutencao da frota de caminhoes.

### Codigo Alterado (Criacao de routes/manutencoes.js)
Criamos o arquivo `routes/manutencoes.js` para isolar o recurso de manutencoes do arquivo principal:

```javascript
const express = require('express');
const router = express.Router();

let manutencoes = [
    { id: 1, caminhao: "Volvo FH 540", tipo: "Troca de oleo", custo: 1500.00 },
    { id: 2, caminhao: "Scania R450", tipo: "Revisao dos freios", custo: 2800.00 }
];

// GET /api/v1/manutencoes
router.get('/', (req, res) => {
    res.status(200).json(manutencoes);
});

// POST /api/v1/manutencoes
router.post('/', (req, res) => {
    const { caminhao, tipo, custo } = req.body;

    if (!caminhao || !tipo || !custo) {
        return res.status(400).json({ erro: "Campos 'caminhao', 'tipo' e 'custo' sao obrigatorios." });
    }

    const novaManutencao = {
        id: manutencoes.length + 1,
        caminhao,
        tipo,
        custo
    };

    manutencoes.push(novaManutencao);
    res.status(201).json(novaManutencao);
});

module.exports = router;
```

### Comandos Executados para Teste
Como as rotas foram vinculadas ao servidor principal protegidas por autenticacao, disparamos a validacao da listagem informando a credencial via terminal:
```bash
curl -s -H "X-API-KEY: binario-tech-secret-2026" http://localhost:3005/api/v1/manutencoes | jq .
```

### Explicacao Tecnica
O uso do `express.Router()` permite desacoplar caminhos especificos do arquivo principal do servidor. O roteador opera como um mini-aplicativo isolado contendo as definicoes locais dos verbos HTTP (GET e POST). Ao final do escopo, exportamos o modulo usando `module.exports` para habilitar o seu consumo e vinculacao por outras partes da arquitetura do software.

O fluxo so e liberado para o roteador interno caso a chave contida no header `X-API-KEY` seja identica ao segredo armazenado no servidor, garantindo a privacidade dos dados.

## Exercicio 04: Criacao de Middleware de Validacao de CNH

### Objetivo
Desenvolver um middleware customizado para interceptar o fluxo de cadastro e validar se o campo correspondente a CNH do motorista atende aos requisitos de infraestrutura e regras de negocio, contendo exatamente 11 digitos numericos.

### Codigo Alterado (Criacao de middlewares/validaCnh.js)
Criamos o arquivo `middlewares/validaCnh.js` utilizando o editor de terminal (`nano middlewares/validaCnh.js`) e inserimos a logica de inspecao de caracteres com comentarios explicativos linha por linha:

```javascript
// Definicao da funcao de middleware que recebe os objetos de requisicao (req), resposta (res) e o gatilho de continuidade (next)
function validaCnhMiddleware(req, res, next) {
    // Captura e desestrutura a propriedade cnh enviada de dentro do corpo da requisicao (payload JSON)
    const { cnh } = req.body;

    // Remove qualquer espaco em branco residual que o usuario possa ter digitado nas pontas da string
    const cnhLimpa = cnh ? cnh.trim() : "";

    // Expressao regular (Regex) para verificar se o texto contem estritamente apenas caracteres numericos de 0 a 9
    const apenasNumeros = /^[0-9]+$/;

    // Condicional de seguranca: Verifica se o campo esta vazio, se o tamanho e diferente de 11 ou se falhou no teste numerico

        // Interrompe o pipeline imediatamente e retorna um HTTP Status 400 (Bad Request) junto com o objeto JSON de erro
        return res.status(400).json({
            erro: "CNH invalida. O campo deve conter exatamente 11 digitos numericos."
        });
    }

    // Se passar em todas as validacoes anteriores, atualiza o corpo da requisicao com a string tratada e limpa
    req.body.cnh = cnhLimpa;

    // Invoca a funcao next() para autorizar o Express a seguir para o proximo middleware ou funcao de rota cadastrada
    next();
}

// Exporta o modulo de middleware para permitir que ele seja importado e utilizado por outros arquivos do servidor
module.exports = validaCnhMiddleware;
```

### Explicacao Tecnica
O middleware atua como uma camada defensiva de software isolada. Ele analisa o objeto `req.body` antes que o endpoint finalize a persistencia dos dados. Caso a string nao possua tamanho igual a 11 ou contenha caracteres alfabeticos, a condicional dispara um `return` precoce devolvendo o status de erro `400 Bad Request`. O metodo `next()` so e invocado se o contrato for cumprido, garantindo a integridade dos dados na memoria.

## Exercicio 05: Aplicacao de Middleware em Rota Especifica e Teste de Rejeicao

### Objetivo
Acoplar o validador de CNH de forma exclusiva na rota POST de motoristas e realizar uma chamada HTTP simulando um payload invalido para comprovar o bloqueio na borda do servidor.

### Codigo Alterado (app.js)
Como mapeado na estrutura do projeto, o middleware `validaCnh` foi importado e injetado diretamente como interceptor na rota de criacao antes do handler final, contendo os comentarios de auditoria:

```javascript
// ... importacoes anteriores e definicoes do Express permanecem iguais

// Importa o middleware de validacao de CNH criado no Exercicio 04 para dentro do escopo do servidor
const validaCnh = require('./middlewares/validaCnh');

// Rota de criacao de motoristas configurada com a injecao do middleware de validacao de CNH no segundo argumento
app.post('/api/v1/motoristas', validaCnh, (req, res) => {
    // Se o middleware executar o next(), esta funcao e ativada e responde com sucesso 201 e mensagem em JSON
    res.status(201).json({ msg: "Motorista cadastrado com sucesso!" });
});

// ... restante das configuracoes do arquivo permanecem iguais
```

### Comando Executado no Terminal para Teste de Falha
Enviamos um payload de teste na porta 3005 contendo uma CNH com apenas 3 digitos ("123") para forcar o comportamento do validador:
```bash
curl -s -i -X POST http://localhost:3005/api/v1/motoristas -H "Content-Type: application/json" -d '{"nome":"Roberto Souza","cnh":"123","categoria":"E"}'
```

### Resposta de Erro Devolvida pelo Servidor
```text
HTTP/1.1 400 Bad Request
Content-Type: application/json; charset=utf-8

{"erro":"CNH invalida. O campo deve conter exatamente 11 digitos numericos."}
```

### Explicacao Tecnica
Ao passar o middleware `validaCnh` como argumento posicional no `app.post`, restringimos o escopo do validador apenas para essa acao. No teste disparado via cURL, a string `"123"` falhou no teste de tamanho (comprimento menor que 11), fazendo o pipeline desviar para o bloco de erro e encerrar a chamada sem tocar na logica interna do endpoint, protegendo os recursos do servidor.
