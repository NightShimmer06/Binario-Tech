## Exercicio 01: Inspecao de Ciclo de Vida de Middleware de Log

### Objetivo
Disparar uma requisicao contra o endpoint publico de saude da aplicacao e auditar a interceptacao dos metadados de rede gerados pelo middleware customizado de log no console do servidor.

### Comando Executado no Terminal
```bash
curl -s http://localhost:3005/api/v1/health | jq .
```

### Exemplo de Logs Capturados no Console
```text
[LOG 2026-10-02T16:10:00.123Z] GET /api/v1/health - Status: 200 (5ms)
```

### Explicacao Tecnica
O `loggerMiddleware` intercepta a requisicao HTTP antes de atingir o handler final. Ele registra a funcao temporizadora inicial e aciona o evento `res.on('finish')`. Quando os buffers de resposta sao completamente descarregados para o cliente (Status 200 OK), o gatilho calcula a diferenca de milissegundos e imprime a linha cronologica formatada, provando o encerramento do ciclo de vida da conexao.

## Exercicio 02: Criacao do Roteador Modular de Manutencoes

### Objetivo
Construir um novo arquivo de rota isolado utilizando o componente Express Router para gerenciar de forma modularizada a listagem e o cadastro de orcamentos de manutencao da frota de caminhoes.

### Codigo Alterado (Criacao de routes/manutencoes.js)
Criamos o arquivo `routes/manutencoes.js` para isolar o recurso de manutencoes do arquivo principal:

```javascript
const express = require('express');
const router = express.Router();

let manutencoes = [
    { id: 1, caminhao: "Volvo FH 540", tipo: "Troca de oleo", custo: 1500.00 },
    { id: 2, caminhao: "Scania R450", tipo: "Revisao dos freios", custo: 2800.00 }
];

// GET /api/v1/manutencoes
router.get('/', (req, res) => {
    res.status(200).json(manutencoes);
});

// POST /api/v1/manutencoes
router.post('/', (req, res) => {
    const { caminhao, tipo, custo } = req.body;

    if (!caminhao || !tipo || !custo) {
        return res.status(400).json({ erro: "Campos 'caminhao', 'tipo' e 'custo' sao obrigatorios." });
    }

    const novaManutencao = {
        id: manutencoes.length + 1,
        caminhao,
        tipo,
        custo
    };

    manutencoes.push(novaManutencao);
    res.status(201).json(novaManutencao);
});

module.exports = router;
```

### Comandos Executados para Teste
Como as rotas foram vinculadas ao servidor principal protegidas por autenticacao, disparamos a validacao da listagem informando a credencial via terminal:
```bash
curl -s -H "X-API-KEY: binario-tech-secret-2026" http://localhost:3005/api/v1/manutencoes | jq .
```

### Explicacao Tecnica
O uso do `express.Router()` permite desacoplar caminhos especificos do arquivo principal do servidor. O roteador opera como um mini-aplicativo isolado contendo as definicoes locais dos verbos HTTP (GET e POST). Ao final do escopo, exportamos o modulo usando `module.exports` para habilitar o seu consumo e vinculacao por outras partes da arquitetura do software.

## Exercicio 04: Criacao de Middleware de Validacao de CNH

### Objetivo
Desenvolver um middleware customizado para interceptar o fluxo de cadastro e validar se o campo correspondente a CNH do motorista atende aos requisitos de infraestrutura e regras de negocio, contendo exatamente 11 digitos numericos.

### Codigo Alterado (Criacao de middlewares/validaCnh.js)
Criamos o arquivo `middlewares/validaCnh.js` utilizando o editor de terminal (`nano middlewares/validaCnh.js`) e inserimos a logica de inspecao de caracteres com comentarios explicativos linha por linha:

```javascript
// Definicao da funcao de middleware que recebe os objetos de requisicao (req), resposta (res) e o gatilho de continuidade (next)
function validaCnhMiddleware(req, res, next) {
    // Linha blindada: Garante que se o req.body nao existir (payload em branco), o codigo usa um objeto vazio e nao quebra o servidor
    const body = req.body || {};
    const cnh = body.cnh;

    // Remove qualquer espaco em branco residual que o usuario possa ter digitado nas pontas da string
    const cnhLimpa = cnh ? String(cnh).trim() : "";

    // Expressao regular (Regex) para verificar se o texto contem estritamente apenas caracteres numericos de 0 a 9 e tamanho exato de 11 digitos
    const apenasNumeros = /^[0-9]{11}$/;

    // Condicional de seguranca: Verifica se o campo falhou no teste do padrao estrutural dos 11 digitos numericos
    if (!apenasNumeros.test(cnhLimpa)) {
        // Interrompe o pipeline imediatamente e retorna um HTTP Status 400 (Bad Request) junto com o objeto JSON de erro
        return res.status(400).json({
            erro: "CNH invalida. O campo deve conter exatamente 11 digitos numericos."
        });
    }

    // Se passar em todas as validacoes anteriores, atualiza o corpo da requisicao com a string tratada e limpa
    req.body.cnh = cnhLimpa;

    // Invoca a funcao next() para autorizar o Express a seguir para o proximo middleware ou funcao de rota cadastrada
    next();
}

// Exporta o modulo de middleware para permitir que ele seja importado e utilizado por outros arquivos do servidor
module.exports = validaCnhMiddleware;
```

### Explicacao Tecnica
O middleware atua como uma camada defensiva de software isolada. Ele analisa o objeto `req.body` antes que o endpoint finalize a persistencia dos dados. O uso da expressao regular `/^[0-9]{11}$/` unifica o teste de tipo e comprimento em uma unica instrucao: o delimitador `{11}` exige contagem exata enquanto os tokens de ancoragem `^` e `$` barram qualquer entrada alfabetica residual, devolvendo `400 Bad Request` em caso de quebra de contrato.

## Exercicio 05: Aplicacao de Middleware em Rota Especifica e Teste de Rejeicao

### Objetivo
Acoplar o validador de CNH de forma exclusiva na rota POST de motoristas e realizar uma chamada HTTP simulando um payload invalido para comprovar o bloqueio na borda do servidor.

### Codigo Alterado (app.js)
Como mapeado na estrutura do projeto, o middleware `validaCnh` foi importado e injetado diretamente como interceptor na rota de criacao antes do handler final, contendo os comentarios de auditoria:

```javascript
// ... importacoes anteriores e definicoes do Express permanecem iguais

// Importa o middleware de validacao de CNH criado no Exercicio 04 para dentro do escopo do servidor
const validaCnh = require('./middlewares/validaCnh');

// Rota de criacao de motoristas configurada com a injecao do middleware de validacao de CNH no segundo argumento
app.post('/api/v1/motoristas', validaCnh, (req, res) => {
    // Se o middleware executar o next(), esta funcao e ativada e responde com sucesso 201 e mensagem em JSON
    res.status(201).json({ msg: "Motorista cadastrado com sucesso!" });
});

// ... restante das configuracoes do arquivo permanecem iguais
```

### Comando Executado no Terminal para Teste de Falha

curl -s -i -X POST http://localhost:3005/api/v1/motoristas \
  -H "Content-Type: application/json" \

### Explicacao Tecnica
Ao passar o middleware `validaCnh` como argumento posicional no `app.post`, restringimos o escopo do validador apenas para essa acao. No teste disparado via cURL, a string `"123"` falhou no teste de tamanho (comprimento menor que 11), fazendo o pipeline desviar para o bloco de erro e encerrar a chamada sem tocar na logica interna do endpoint, protegendo os recursos do servidor.

## Exercicio 06: Tratamento de Rotas Inexistentes com Middleware Global 404

### Objetivo
Validar o comportamento do middleware global de captura de rotas residuais, garantindo que qualquer tentativa de acesso a endpoints nao catalogados seja devidamente interceptada e respondida com uma estrutura JSON padronizada.

### Codigo Alterado (app.js)
Certificamos a presenca do middleware de fechamento pos-rotas no arquivo `app.js`, contendo os comentarios explicativos detalhados linha por linha:

```javascript
// Declaracao do middleware de captura global colocado estrategicamente apos a definicao de todas as rotas validas da API
app.use((req, res) => {
    // Intercepta qualquer requisicao que nao deu match com os caminhos anteriores e injeta explicitamente o Status Code 404 (Not Found)
    res.status(404)
    // Despacha imediatamente para o cliente um objeto JSON estruturado contendo a mensagem de erro padronizada do sistema
    .json({ 
        erro: "Endpoint nao encontrado no servidor Binario Tech." 
    });
});
```

### Comando Executado no Terminal para Teste
Disparamos um cURL contra um recurso ficticio chamado `/api/v1/clientes` na porta 3005 para testar o interceptador:
```bash
curl -s http://localhost:3005/api/v1/clientes | jq .
```

### Resposta JSON Obtida no Terminal
```json
{
  "erro": "Endpoint nao encontrado no servidor Binario Tech."
}
```

### Explicacao Tecnica
O Express processa os middlewares e rotas na ordem exata em que sao declarados no arquivo. Quando nenhuma rota anterior coincide com o metodo e a URL digitados pelo cliente, o fluxo cai obrigatoriamente no middleware residual final. Ao omitir um caminho de rota no primeiro argumento do `app.use`, dizemos ao Express para executar esse bloco para qualquer URL restante, convertendo o erro de rota padrao do framework (HTML) em um payload JSON limpo.

## Exercicio 07: Script Bash de Auditoria de Seguranca

### Objetivo
Construir um script em Bash automatizado que simula multiplas quebras de contrato de autenticacao e um acesso bem-sucedido, persistindo todo o fluxo em um arquivo de log acumulativo para fins de auditoria de seguranca.

### Codigo Alterado (Criacao de teste_seguranca.sh)
Criamos o arquivo `teste_seguranca.sh` na raiz da pasta `aula05` utilizando o editor de terminal (`nano teste_seguranca.sh`) com os comentarios linha por linha em cada instrucao do script:

```bash
#!/bin/bash
# Declaracao do Shebang que instrui o interpretador do sistema operacional a executar este arquivo utilizando o binario do Bash

# Grava a primeira linha do cabecalho e usa o operador '>' para limpar o arquivo audit_seguranca.log e inicia-lo do zero
echo "=========================================" > audit_seguranca.log

# Adiciona o titulo do relatorio de auditoria ao final do arquivo de log utilizando o operador de anexo '>>'
echo "  AUDITORIA DE SEGURANCA - BINARIO TECH  " >> audit_seguranca.log

# Captura dinamicamente a data e a hora do sistema operacional e anexa no cabecalho estruturado do documento
echo "  Data/Hora do Teste: $(date)            " >> audit_seguranca.log

# Fecha a estrutura visual do cabecalho inicial injetando a linha divisoria de caracteres no arquivo de texto
echo "=========================================" >> audit_seguranca.log

# Inicializa um laco de repeticao 'for' que vai iterar sequencialmente de 1 ate 3 para simular as falhas consecutivas
for i in {1..3}
do
   # Imprime uma mensagem de aviso no log indicando o numero atual da tentativa de acesso mal-sucedida
   echo -e "\n[TESTE] Tentativa $i de acesso nao autorizado à rota protegida:" >> audit_seguranca.log
   
   # Dispara uma requisicao HTTP silenciosa via cURL sem passar cabeçalhos de autenticacao e anexa o JSON de erro 401 no log
   curl -s http://localhost:3005/api/v1/manutencoes >> audit_seguranca.log
done
# Encerra o bloco de execucao do laco de repeticao for apos concluir as 3 iteracoes programadas

# Insere duas quebras de linha e o titulo do teste de sucesso para fins de organizacao visual do relatorio de auditoria
echo -e "\n\n[TESTE] Tentativa de acesso autorizado com X-API-KEY valida:" >> audit_seguranca.log

# Dispara a chamada HTTP enviando o header 'X-API-KEY' valido, fazendo a API liberar o JSON com a lista de manutencoes para o log
curl -s -H "X-API-KEY: binario-tech-secret-2026" http://localhost:3005/api/v1/manutencoes >> audit_seguranca.log

# Adiciona uma linha divisoria final de fechamento para isolar os blocos de dados gravados pela automacao
echo -e "\n-----------------------------------------" >> audit_seguranca.log

# Grava a mensagem conclusiva de encerramento do script, confirmando a persistencia dos dados com sucesso em disco
echo "Rotina de auditoria de seguranca concluida!" >> audit_seguranca.log
```

### Comandos de Execucao e Verificacao
```bash
# 1. Concede permissao de execucao para o arquivo do script Bash
chmod +x teste_seguranca.sh

# 2. Executa a esteira automatizada de testes de seguranca
./teste_seguranca.sh

# 3. Faz a leitura do arquivo de logs gerado pela automacao para validar os retornos
cat audit_seguranca.log
```

### Explicacao Tecnica
O script centraliza e simula o comportamento de um cliente consumindo a API protegida. O operador `>` e util para resetar o log a cada nova execucao, enquanto o operador `>>` anexa os payloads de erro `401 Unauthorized` gerados pelo `authMiddleware` e, por fim, o payload de sucesso `200 OK`, empacotando os resultados em uma linha do tempo de auditoria persistente em disco para analise posterior da equipe de infraestrutura.

## Exercicio 08: Monitoramento e Finalizacao Limpa de Processos

### Objetivo
Localizar o numero de registro unico (PID) do servidor Node.js que foi colocado para rodar em segundo plano utilizando as ferramentas nativas de gerenciamento de processos do Linux e encerra-lo de forma limpa e forcada.

### Comandos Executados no Terminal
```bash
# 1. Filtra a lista geral de tarefas do sistema para exibir apenas as runtimes Node ativas da sua conta
ps aux | grep node
```

### Exemplo de Retorno do Terminal (Identificacao do PID)
```text
caroline    125430  0.4  0.5 582104 42100 pts/1    S    16:30   0:02 node app.js
caroline    125488  0.0  0.0  14428  1024 pts/1    S+   16:32   0:00 grep node
```

> **Como realizar a leitura dos metadados:** O identificador numerico do PID fica localizado fixo na segunda coluna da tabela, logo apos o nome da sua conta de usuaria. No cenario mapeado acima, o identificador correto do processo do servidor e o **125430** (a segunda linha reflete apenas a execucao do proprio comando grep).

```bash
# 2. Envia o sinal de interrupcao forcada utilizando o ID mapeado na coluna da tabela do Kernel
kill -9 125430
```

### Explicacao Tecnica
O comando `ps aux` varre de forma abrangente a arvore de tarefas ativa gerenciada pelo Kernel do Linux. O caractere pipe `|` atua desviando esses dados textuais brutos para a entrada do utilitario `grep node`, que funciona como um filtro cirurgico imprimindo apenas as linhas que contem a palavra-chave informada. Ao disparar a instrucao `kill` acompanhada da flag `-9` e do numero identificador mapeado, o sistema operacional envia o sinal nao-bloqueavel SIGKILL diretamente ao processo, interrompendo imediatamente a execucao do binario Express e liberando a porta 3005 na pilha de rede do servidor compartilhado.
