# Atividade Pratica - Aula 06: Persistencia em Disco com fs/promises e APIs RESTful

Este repositorio contem a resolucao da bateria de exercicios praticos da Aula 06, focada na persistencia e recuperacao de dados estruturados em arquivos JSON locais utilizando o modulo nativo 'fs/promises' do Node.js, tratamento de excecoes de I/O e manipulacao assincrona.

---

## Exercicios de Fixacao

* **EXERCICIO 01:** Efetue uma requisicao GET na rota '/api/v1/ocorrencias' via cURL/httpie e valide se a resposta e um array contendo os registros do arquivo 'ocorrencias.json'.
* **EXERCICIO 02:** Utilize o utilitario 'jq' para filtrar do arquivo 'ocorrencias.json' apenas os registros da montadora "Scania".
* **EXERCICIO 03:** Adicione uma rota GET '/api/v1/ocorrencias/montadora/:nome' que filtra as ocorrencias registradas em arquivo de acordo com a montadora informada na URL.
* **EXERCICIO 04:** Crie uma nova rota DELETE '/api/v1/ocorrencias/:id' que remove do arquivo JSON a ocorrencia correspondente ao ID informado.
* **EXERCICIO 05:** Crie um script em Bash chamado 'limpar_dados.sh' que encerra o processo Node.js e exclui o arquivo 'ocorrencias.json' para resetar o ambiente de testes.

## Exercicio 01: Requisicao e Validacao de Persistencia em Disco

### Objetivo
Disparar uma requisicao HTTP do tipo GET contra o endpoint de ocorrencias e validar se o Express consegue ler o arquivo fisico 'ocorrencias.json' armazenado no disco do servidor, retornando a estrutura em formato JSON.

### Comando Executado no Terminal
Para manter a consistencia com os ambientes anteriores, efetuamos a chamada apontando para a porta 3005 utilizando o cURL acoplado ao jq:
```bash
curl -s http://localhost:3005/api/v1/ocorrencias | jq .
```

### Resposta Obtida no Terminal (Exemplo de Array Persistido)
```json
[
  {
    "id": 1723567890123,
    "montadora": "Scania",
    "placa": "SCA-9988",
    "descricao": "Superaquecimento de motor",
    "gravidade": "ALTA",
    "data_registro": "2026-08-13T14:22:15.000Z"
  }
]
```

### Explicacao Tecnica
Quando a rota recebe a requisicao GET, ela invoca a funcao assincrona auxiliar `lerOcorrencias()`. Essa funcao executa o metodo `fs.readFile()` de forma nao-bloqueante na linha de execucao do Node.js. O buffer lido do disco do sistema operacional e convertido para string ('utf-8') e parseado para um array de objetos pelo `JSON.parse()`. Caso o arquivo fisico nao exista no diretorio local, o bloco `catch` intercepta o erro de I/O, invoca o `fs.writeFile()` para inicializar um arquivo limpo contendo apenas colchetes vazios `[]`, retornando a lista integra ao cliente sem derrubar o runtime do Express.

## Exercicio 02: Filtragem de Dados Estruturados com Utilitario jq

### Objetivo
Utilizar o processador de texto JSON via linha de comando (`jq`) para inspecionar o arquivo fisico 'ocorrencias.json' e extrair de forma cirurgica apenas os registros pertencentes a montadora "Scania".

### Comando Executado no Terminal
Executamos a leitura do arquivo local passando o filtro de selecao por propriedade diretamente para o interpretador do jq:
```bash
cat ocorrencias.json | jq '.[] | select(.montadora == "Scania")'
```

### Resposta Obtida no Terminal (Filtro Aplicado)
```json
{
  "id": 1723567890123,
  "montadora": "Scania",
  "placa": "SCA-9988",
  "descricao": "Superaquecimento de motor",
  "gravidade": "ALTA",
  "data_registro": "2026-08-13T14:22:15.000Z"
}
```

### Explicacao Tecnica
O utilitario `jq` funciona como um motor de busca e transformacao para estruturas JSON no terminal. A instrucao `.[]` diz para o programa abrir o array principal e iterar por cada objeto contido nele individualmente. O caractere pipe interno `|` repassa esses objetos para a funcao `select()`. A condicional `.montadora == "Scania"` atua avaliando o valor da chave mapeada, imprimindo na tela apenas os blocos que atendem ao criterio de igualdade exata e descartando os demais registros gravados em disco.

## Exercicio 03: Rota de Consulta Filtrada por Montadora

### Objetivo
Adicionar um novo endpoint na API utilizando o metodo GET e parametros de rota (`:nome`) para permitir que o cliente consulte e filtre ocorrencias persistidas em disco com base no nome de uma montadora especifica.

### Codigo Alterado (ocorrencias_api.js)
Editamos o arquivo `ocorrencias_api.js` utilizando o editor de terminal (`nano ocorrencias_api.js`) e inserimos a nova rota de consulta dinamica com comentarios explicativos linha por linha:

```javascript
// ... rotas anteriores (Listar e Cadastrar) permanecem iguais no arquivo

// Rota GET configurada para capturar o nome da montadora de forma dinamica atraves do parametro ':nome' na URL
app.get('/api/v1/ocorrencias/montadora/:nome', async (req, res) => {
    try {
        // Captura o valor do parametro enviado na URL e converte todo o texto para letras maiusculas para evitar conflitos de caixa
        const montadoraBusca = req.params.nome.toUpperCase();

        // Invoca a funcao auxiliar assincrona para ler o arquivo JSON completo direto do disco rigido do servidor
        const ocorrencias = await lerOcorrencias();

        // Utiliza o metodo nativo .filter() do JavaScript para varrer o array e separar apenas os registros correspondentes
        const ocorrenciasFiltradas = ocorrencias.filter(o => {
            // Garante que o valor salvo na propriedade montadora tambem seja comparado em caixa alta para uma busca precisa
            return o.montadora.toUpperCase() === montadoraBusca;
        });

        // Retorna o HTTP Status Code 200 (OK) despachando a nova lista filtrada em formato JSON para o cliente
        res.status(200).json(ocorrenciasFiltradas);

    } catch (erro) {
        // Bloco de contingencia: Caso ocorra alguma falha na leitura do disco, devolve o erro 500 (Internal Server Error)
        res.status(500).json({ 
            erro: "Erro interno ao processar a filtragem de dados em disco." 
        });
    }
});

// O encerramento do arquivo com o app.listen permanece inalterado
```

### Comando Executado no Terminal para Teste
Após reiniciar o servidor para carregar a nova rota na memória, disparamos a validação passando a montadora desejada diretamente no caminho da URL na porta 3005:
```bash
curl -s http://localhost:3005/api/v1/ocorrencias/montadora/Scania | jq .
```

### Explicacao Tecnica
O endpoint utiliza parâmetros dinâmicos mapeados pelo Express através do objeto `req.params`. A lógica de negócio lê a base de dados em disco chamando o método assíncrono com `await`, mitigando o bloqueio da thread principal do Node.js. A filtragem em memória com `.filter()` assegura que apenas as ocorrências cujo critério de igualdade de strings coincida com o parâmetro recebido sejam selecionadas, devolvendo um array limpo ao cliente e mantendo a integridade dos dados originais no arquivo JSON.

## Exercicio 04: Rota de Remocao de Ocorrencias por ID

### Objetivo
Adicionar um novo endpoint na API utilizando o verbo HTTP DELETE e parametros de URL para localizar, remover um registro especifico de ocorrencia pelo seu identificador unico (ID) e salvar o arquivo JSON atualizado de volta no disco.

### Codigo Alterado (ocorrencias_api.js)
Editamos o arquivo `ocorrencias_api.js` utilizando o editor de terminal (`nano ocorrencias_api.js`) e implementamos a rota de remocao com comentarios detalhados linha por linha:

```javascript
// ... rotas anteriores permanecem inalteradas no arquivo

// Rota DELETE configurada para receber o identificador unico do registro atraves do parametro ':id' na URL
app.delete('/api/v1/ocorrencias/:id', async (req, res) => {
    try {
        // Captura o id enviado na URL e converte o texto para o formato numerico correspondente ao Date.now() salvo
        const idBusca = parseInt(req.params.id);

        // Invoca a funcao auxiliar assincrona para carregar a lista de ocorrencias direto do arquivo JSON em disco
        const ocorrencias = await lerOcorrencias();

        // Utiliza o metodo .find() para verificar se o ID fornecido pelo cliente realmente existe na base de dados
        const existeOcorrencia = ocorrencias.find(o => o.id === idBusca);

        // Condicional de seguranca: Caso o registro nao seja localizado, interrompe o fluxo imediatamente
        if (!existeOcorrencia) {
            // Retorna o HTTP Status Code 404 (Not Found) informando que o recurso nao foi localizado para exclusao
            return res.status(404).json({ 
                erro: "Ocorrencia nao encontrada para remocao na base de dados." 
            });
        }

        // Utiliza o metodo .filter() para gerar um novo array contendo todos os registros, EXCETO o que possui o ID correspondente
        const ocorrenciasRestantes = ocorrencias.filter(o => o.id !== idBusca);

        // Invoca a funcao auxiliar assincrona passando a nova lista limpa para reescrever o arquivo ocorrencias.json no disco
        await salvarOcorrencias(ocorrenciasRestantes);

        // Retorna o HTTP Status Code 200 (OK) enviando um payload JSON de confirmacao do sucesso da operacao
        res.status(200).json({ 
            mensagem: "Ocorrencia removida com sucesso da base de dados local.",
            id_removido: idBusca
        });

    } catch (erro) {
        // Bloco de contingencia: Trata falhas inesperadas de leitura/escrita devolvendo o erro 500 (Internal Server Error)
        res.status(500).json({ 
            erro: "Erro interno ao processar a exclusao do registro no disco rigido." 
        });
    }
});

// O encerramento do arquivo com o app.listen permanece igual
```

### Comando Executado no Terminal para Teste
Após reiniciar o servidor para aplicar a nova rota, efetuamos a chamada informando o ID da ocorrência que desejamos remover (ajuste o número do ID conforme o gerado no seu arquivo):
```bash
curl -s -X DELETE http://localhost:3005/api/v1/ocorrencias/1723567890123 | jq .
```

### Explicacao Tecnica
O metodo DELETE remove recursos especificos mapeados por identificadores unicos. A logica utiliza o metodo `.find()` como uma barreira de seguranca para evitar processamentos desnecessarios em disco caso o ID seja invalido, disparando o erro `404 Not Found`. Estando correto, o filtro `.filter()` isola o objeto alvo e a funcao `salvarOcorrencias()` invoca internamente o modulo `fs.writeFile()`, reescrevendo a estrutura JSON inteira no armazenamento fisico com o registro eliminado, garantindo a consistencia do estado da aplicacao.

## Exercicio 05: Script Bash de Limpeza e Reinicializacao do Ambiente

### Objetivo
Construir um script automatizado em Bash que encerra de forma limpa as instancias ativas da API Node.js rodando em segundo plano e remove o arquivo fisico 'ocorrencias.json' do disco para resetar completamente a base de dados de testes.

### Codigo Alterado (Criacao de limpar_dados.sh)
Criamos o arquivo `limpar_dados.sh` na raiz da pasta `aula06` utilizando o editor de terminal (`nano limpar_dados.sh`) com os comentarios explicativos detalhados linha por linha:

```bash
#!/bin/bash
# Declaracao do Shebang que instrui o interpretador do sistema operacional a executar este arquivo utilizando o binario do Bash

echo "=========================================="
echo "   RESETE DE AMBIENTE - API DE OCORRÊNCIAS"
echo "=========================================="

echo "[1/3] Encerrando processos antigos do Node.js..."
# Sinaliza o encerramento limpo apenas das runtimes do Node.js ativas sob a conta da usuaria atual
# O operador '2>/dev/null' descarta avisos de erro caso nenhum processo esteja em execucao no momento
killall -u caroline.sagaes node 2>/dev/null

# O comando '|| true' serve como uma trava de seguranca para garantir que o script nao pare caso a linha anterior de erro
echo "--> Instâncias em background finalizadas." || true

echo -e "\n[2/3] Removendo arquivo de dados físico do disco..."
# Utiliza o comando 'rm -f' para remover o arquivo ocorrencias.json de forma forcada sem pedir confirmacao no console
if [ -f "ocorrencias.json" ]; then
    rm -f ocorrencias.json
    echo "--> Arquivo ocorrencias.json excluido com sucesso."
else
    echo "--> O arquivo ocorrencias.json nao existia no diretorio local."
fi

echo -e "\n[3/3] Verificando integridade da limpeza..."
# Lista os arquivos locais para comprovar que o arquivo JSON de dados nao consta mais no diretorio
ls -la ocorrencias.json 2>/dev/null

echo "=========================================="
echo "Ambiente resetado com sucesso e pronto para novos testes!"
```

### Comandos de Execucao e Verificacao
```bash
# 1. Concede a permissao de execucao obrigatoria para o arquivo do script Bash
chmod +x limpar_dados.sh

# 2. Executa a rotina automatizada de limpeza do ecossistema local
./limpar_dados.sh
```

### Explicacao Tecnica
O script automatiza tarefas de manutencao do ambiente de homologacao. O comando `killall -u` atua limpando as conexoes presas na porta 3005 do usuario de forma segura. A condicional bash `[ -f ]` inspeciona a existencia do arquivo de armazenamento permanente em disco antes de invocar a chamada do utilitario `rm`, evitando erros na esteira de scripts. Esse procedimento limpa o estado da aplicacao, permitindo que a funcao `lerOcorrencias()` inicialize um novo banco de dados relacional em disco zerado (`[]`) na proxima inicializacao da API.
