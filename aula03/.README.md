# Atividade Pratica - Aula 03: Ambiente de Desenvolvimento Web e Ferramentas CLI

Este repositorio contem a resolucao da bateria de exercicios praticos da Aula 03, focada em inspecao de rotas HTTP com cURL e HTTPie, tratamento de payloads JSON com jq, gerenciamento de pacotes (npm/apt) e automacao com scripts Bash.

---

## Exercicios de Fixacao

* **EXERCICIO 01:** Efetue uma requisicao GET para a rota '/api/v1/scania' via cURL e use o 'jq' para exibir somente a chave 'modelo'.
* **EXERCICIO 02:** Faça uma requisicao para a rota '/api/v1/mercedes' utilizando a ferramenta 'httpie' e salve o resultado no arquivo 'mercedes.json'.
* **EXERCICIO 03:** Utilize o 'jq' para ler o arquivo 'mercedes.json' e filtrar apenas o valor do campo 'status'.
* **EXERCICIO 04:** Edite o arquivo 'telemetria.js' e adicione uma nova rota '/api/v1/volvo' retornando os dados do modelo 'FH 540'. Reinicie a aplicacao e teste a rota.
* **EXERCICIO 05:** Configure o arquivo 'package.json' adicionando um script "start": "node telemetria.js". Teste a execucao usando 'npm start'.
* **EXERCICIO 06:** Crie um comando que direcione o resultado da auditoria do script 'testar_telemetria.sh' para um arquivo de log chamado 'relatorio.log'.
* **EXERCICIO 07:** Filtre a resposta da rota '/api/v1/vw' para exibir apenas os campos 'montadora' e 'status' em uma unica chamada 'jq'.
* **EXERCICIO 08:** Localize o PID do processo Node.js em execucao no seu terminal usando 'ps aux | grep node' e encerre-o com o comando 'kill -9 <PID>'.

## Exercicio 01: Filtragem de Propriedade JSON com cURL e jq

### Objetivo
Realizar uma chamada HTTP do tipo GET na rota da Scania e extrair de forma isolada o valor da propriedade "modelo" diretamente pelo terminal.

### Comando Executado
```bash
curl -s http://localhost:3001/api/v1/scania | jq '.modelo'
```

### Explicacao Tecnica
A flag `-s` (silent) remove as barras de progresso do cURL do terminal. O caractere pipe `|` redireciona a resposta de texto cru gerada pela API para a entrada do utilitario `jq`. O filtro `.modelo` localiza a chave correspondente dentro do objeto JSON e retorna apenas o seu valor em texto ("R450").

## Exercicio 02: Inspecao HTTP e Escrita em Disco com HTTPie

### Objetivo
Instalar a ferramenta HTTPie por meio do gerenciador de pacotes, consumir a rota da Mercedes-Benz e persistir os dados obtidos diretamente em um arquivo fisico no servidor.

### Comando para Instalacao da Ferramenta
```bash
sudo apt-get update && sudo apt-get install -y httpie
```

### Comando Executado para o Exercicio
```bash
http GET http://localhost:3001/api/v1/mercedes > mercedes.json
```

### Explicacao Tecnica
O HTTPie possui uma sintaxe mais legivel comparada ao cURL. Ao utilizar o operador de redirecionamento do Bash `>`, o fluxo de caixa de saida que seria renderizado na tela e interceptado e gravado de forma limpa na estrutura do arquivo `mercedes.json` criado na raiz do diretorio.

## Exercicio 03: Leitura e Analise de Arquivo Local com jq

### Objetivo
Utilizar o interpretador de JSON para abrir e auditar o arquivo gerado na etapa anterior, recuperando isoladamente a propriedade "status".

### Comando Executado
```bash
jq '.status' mercedes.json
```

### Explicacao Tecnica
Diferente do Exercicio 01 onde o `jq` recebeu os dados de um fluxo de rede via pipe, aqui o `jq` le o arquivo local `mercedes.json` passado como segundo argumento. O filtro `.status` varre o arquivo e extrai o valor string armazenado ("OK").

## Exercicio 04: Criacao de Novas Rotas no Express

### Objetivo
Modificar a API original para dar suporte ao monitoramento de uma nova montadora (Volvo), disponibilizando os dados tecnicos do modelo FH 540.

### Codigo Original (telemetria.js)
O servidor original contava apenas com as rotas Scania, Mercedes e VW instaladas:
```javascript
// Apenas as rotas anteriores existiam aqui...
app.listen(PORT, () => { ... });
```

### Codigo Alterado (telemetria.js)
Editamos o arquivo `telemetria.js` utilizando o editor de terminal (`nano telemetria.js`) e inserimos a nova rota antes do metodo `listen`:

```javascript
// ... rotas anteriores permanecem iguais

// Nova Rota Volvo adicionada para o Exercicio 04
app.get('/api/v1/volvo', (req, res) => {
    res.json({ 
        montadora: "Volvo", 
        modelo: "FH 540", 
        status: "OK", 
        conexao: true, 
        velocidade_media: 80 
    });
});

app.listen(PORT, () => {
    console.log(`[Binario Tech] Servidor de Telemetria rodando em http://localhost:${PORT}`);
});
```

### Comandos para Teste
Como o processo estava rodando em background, reiniciamos a aplicacao ou subimos o servidor novamente e disparamos a validacao via terminal:
```bash
curl -s http://localhost:3001/api/v1/volvo | jq .
```

### Explicacao Tecnica
Adicionamos um novo endpoint HTTP mapeando o verbo GET para o caminho `/api/v1/volvo`. O metodo `res.json` encarrega-se de estruturar o objeto Javascript e injetar os cabecalhos de resposta corretos (`Content-Type: application/json`), permitindo que as ferramentas de CLI consumam a nova rota de telemetria sem problemas.

## Exercicio 05: Automacao de Scripts com npm

### Objetivo
Configurar o gerenciador de pacotes da aplicacao para criar um atalho de inicializacao padronizado, eliminando a execucao manual direta com o comando bruto do Node.js.

### Codigo Original (package.json)
O arquivo gerado automaticamente pelo comando `npm init -y` possuia apenas o script de testes padrao em branco:
```json
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1"
  }
```

### Codigo Alterado (package.json)
Editamos o arquivo `package.json` para acoplar a instrucao "start" dentro do objeto de scripts:

```json
  "scripts": {
    "test": "echo \"Error: no test specified\" && exit 1",
    "start": "node telemetria.js"
  }
```

### Comando Executado
```bash
npm start
```

### Explicacao Tecnica
O objeto `scripts` no `package.json` serve para documentar e padronizar o ciclo de vida do projeto. Ao mapear o comando `node telemetria.js` para a chave `start`, permitimos que qualquer desenvolvedor ou ferramenta de integracao continua inicialize o ecossistema usando uma sintaxe universal (`npm start`), abstraindo o arquivo inicial real da aplicacao.

## Exercicio 06: Redirecionamento de Saida e Criacao de Logs

### Objetivo
Executar o script de automacao em Bash criado na aula e desviar toda a sua saida visual para um arquivo de log permanente, impedindo que o resultado suma do terminal.

### Comando Executado
```bash
./testar_telemetria.sh > relatorio.log
```

### Explicacao Tecnica
O operador de redirecionamento `>` captura o fluxo de saida padrao (stdout) gerado pelos comandos internos do script `testar_telemetria.sh`. Em vez de exibir o texto na tela do terminal, o Bash cria o arquivo `relatorio.log` (ou sobrescreve o existente) e descarrega todo o relatorio da auditoria nele de forma persistente.

## Exercicio 07: Filtragem Multipla em Chamada Unica com jq

### Objetivo
Consumir o endpoint da Volkswagen e tratar o payload recebido para extrair simultaneamente mais de um campo (montadora e status) usando apenas uma instrucao de filtro.

### Comando Executado
```bash
curl -s http://localhost:3001/api/v1/vw | jq '{montadora: .montadora, status: .status}'
```

### Explicacao Tecnica
Para filtrar multiplos campos ao mesmo tempo e manter a estrutura valida, passamos uma expressao de criacao de objeto `{}` dentro do `jq`. O interpretador le o JSON bruto vindo da rota da VW, extrai as chaves especificadas e monta um novo mini-objeto contendo apenas o par de informacoes desejadas, descartando o restante das propriedades.

## Exercicio 08: Monitoramento de Processos e Encerramento Forcado

### Objetivo
Identificar o numero de registro unico (PID) do servidor Node.js que foi colocado para rodar em segundo plano e finalizar a sua execucao de forma forcada pelo sistema operacional.

### Comandos Executados
```bash
# 1. Localiza o processo Node.js ativo e identifica o seu PID
ps aux | grep node
```

### Exemplo de Saida do Terminal
Ao rodar o comando acima, o terminal retorna linhas parecidas com esta:
```text
usuario    14820  0.5  0.4 570084 38204 pts/0    S    16:00   0:01 node telemetria.js
usuario    14855  0.0  0.0  14428  1012 pts/0    S+   16:02   0:00 grep node
```

> **Identificacao do PID:** O numero do PID e o primeiro identificador numerico que aparece logo apos o nome do usuario. No exemplo acima, o processo correspondente ao servidor Node.js e o **14820** (a segunda linha indica apenas o proprio comando grep que voce acabou de rodar).

```bash
# 2. Encerra o processo utilizando o PID localizado na tabela
kill -9 14820
```

### Explicacao Tecnica
O comando `ps aux` lista todos os processos ativos na maquina. O pipe `|` envia essa lista para o `grep node`, que filtra e mostra apenas as linhas que contem a palavra "node", onde localiza-se o numero do PID na segunda coluna da tabela. O comando `kill -9` envia o sinal de finalizacao imediata SIGKILL para o ID mapeado, interrompendo o loop e liberando a porta 3001 no sistema operacional.
